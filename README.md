# dv4calib — 로봇 마스크를 이용한 능동 카메라-로봇 보정 (D v4)

dv4calib는 이진 로봇 마스크로 로봇 베이스에 대한 고정 카메라의 자세를 추정합니다. 또 다음 영상을 찍을 때 로봇이 어디로
움직여야 하는지도 골라 줍니다.
- **사용자가 주는 것:** 카메라 내부 행렬, 초기 카메라 자세, 그리고 뷰마다 관절각과 로봇 마스크.

지원 환경: **xArm7**(로봇 모형 내장)과 **고정 카메라 1대**. 

## 입력과 출력

| 입력 | 형식 |
|---|---|
| `K` | 3×3 카메라 내부 행렬 (픽셀 단위, 왜곡을 보정한 영상 기준) |
| `T_init` | 4×4 초기 자세 == pvnet결과 |
| `q` (뷰마다) | 팔 관절각 7개, 라디안 단위, 내장 URDF의 규약 |
| `mask` (뷰마다) | 같은 왜곡 보정 영상에서 얻은 H×W 배열.== pointrender 결과 |
| `robot` (선택) | 기본값은 내장 xArm7의 URDF·SRDF·메시입니다. 같은 파일 구조의 사본을 쓰려면 `dv4calib.xarm7(경로)`를 넘깁니다. |

| 출력 | |
|---|---|
| 카메라 자세 | 뷰마다 4×4 추정값 (카메라 ← 베이스) |
| 불확실성 | 로봇 베이스 좌표계에서의 카메라 위치 표준편차(mm, x y z)와 카메라 방향 표준편차(도, 회전 벡터) |
| 적합 품질 | 뷰마다 적합된 실루엣과 마스크의 겹침(IoU), 평균 경계 오차(픽셀) |
| 다음 뷰 | 다음 영상을 찍을 관절각 7개. 공개된 프로토콜과 같이 7번 관절은 0이고, 집게는 움직이지 않습니다. |
| 결정 기록 | 뷰마다 시작점, 후보, 경로 검사, 소요 시간 |

## 설치

필요 환경은 리눅스, Python 3.10 또는 3.11(SAPIEN 2.2 휠 기준), CUDA 툴킷이 있는 CUDA GPU입니다. SAPIEN은 Vulkan
로더와 OpenGL/X11 라이브러리도 필요합니다. 우분투라면 `apt install libvulkan1 libgl1 libx11-6`로 설치합니다.

```bash
# 1. CUDA용 PyTorch (시험 환경: Python 3.10, PyTorch 2.5.1 + CUDA 11.8, RTX 3090). pytorch.org 참고
# 2. nvdiffrast: 설치된 PyTorch에 맞춰 CUDA 커널을 컴파일하므로 빌드 격리 없이 설치
pip install --no-build-isolation git+https://github.com/NVlabs/nvdiffrast.git
# 3. 나머지 의존성과 패키지 자체 (예제와 사용자 스크립트가 import함)
pip install -r requirements.txt
pip install -e .
```

첫 보정 때 여유 거리 제약에 쓰는 거리장을 한 번 계산합니다. 약 8분, 60 MB가 걸리며, 결과는 `~/.cache/dv4calib`
또는 `DV4_CACHE` 환경 변수가 가리키는 폴더에 저장됩니다.

## 빠른 시작

**합성 예제.** 패키지가 알려진 카메라 자세에서 마스크를 직접 렌더하고, 5개 뷰로 보정합니다. 마스크를 만든 렌더러로
그대로 적합하므로 실제 정확도가 아니라 설치와 반복 과정이 제대로 도는지를 확인하는 용도입니다.

```bash
python examples/synthetic.py --out dv4calib_synthetic
```

**파이썬.** `capture` 함수는 로봇을 움직인 뒤 새 마스크(또는 `(도달한 관절각, 마스크)`)를 돌려줍니다.

```python
from dv4calib import Calibrator

cal = Calibrator(K, T_init, q1, mask1, workdir="runs/cam0")   # workdir(선택): 기록 저장 폴더
T_cam_from_base = cal.run(capture, n_views=5)
cal.history[-1]["position_std_mm"], cal.history[-1]["rotation_std_deg"]
```

반복을 직접 제어하는 방법은 다음과 같습니다.
- `cal.next_view()`: 다음 `q7`과 결정 정보를 돌려줍니다.
- `cal.add_view(q, mask)`: 새로 찍은 뷰를 추가합니다.
- `cal.fit()`: 적합을 다시 합니다.
- `cal.estimate()`: 현재 4×4 자세를 돌려줍니다.

실제 로봇에 붙일 틀은 `examples/robot_loop.py`에 있습니다.

**자료 폴더를 쓰는 명령줄.**

```
data/
  K.txt              3x3 내부 행렬
  T_init.txt         4x4 초기 자세 (카메라 <- 베이스)
  views/01/q.txt     관절각 7개 (라디안)
  views/01/mask.png  로봇 마스크 (0이 아닌 값 = link_base, link1..link7)
  views/02/...       찍은 순서대로 이후 뷰
```

```bash
python -m dv4calib next data/        # data/dv4calib_out/{next_q.txt, estimate.txt, summary.json, ...} 생성
# next_q.txt의 자세로 로봇을 옮기고 새 뷰를 data/views/02/{q.txt, mask.png}로 저장한 뒤 다시 next 실행, ...
python -m dv4calib estimate data/    # 지금까지의 뷰로 자세와 불확실성 계산
```

`next`는 매번 직전 결정을 이어 시작점(warm start)으로 씁니다(순차 방법과 동일). 단, 그 결정이 같은 이전 뷰들로
계산된 경우에만 씁니다. 뷰 폴더는 숫자 순서로 읽습니다(`2`가 `10`보다 앞).

## 작동 원리

뷰 k = 1, 2, …마다 다음을 합니다.

1. **적합 (`fit.py`).**
   - 현재 추정 자세에서 로봇을 렌더하고, 윤곽 픽셀마다 관측 마스크까지의 부호 있는 경계 거리를 잽니다.
   - 모든 뷰를 써서 `T_init`에서 출발하고, Huber 손실(0.5 px)을 쓰는 Gauss–Newton으로 6자유도 자세를 풉니다.
   - 그다음 잔차에서 다시 추정한 뷰·링크별 Laplace 잡음 척도로 가중치를 다시 줍니다.
   - 경계 야코비안은 각 윤곽점의 법선 방향 영상 이동이며, 중앙 차분으로 계산합니다.
2. **사후분포 (`posterior.py`).** 추정값에서 Laplace 근사 `Σ = b_blk · I⁻¹`를 만듭니다.
   - `I`는 모든 뷰의 윤곽 픽셀 정보를 더한 것입니다. 링크별 잡음 척도로 가중하며, 잡음 척도의 하한은 0.25 px입니다.
   - `b_blk`는 뷰 1 잔차의 상관 길이입니다.
   - 사후 표본을 8개 뽑습니다.
3. **위험값.** `R(q) = b_blk/9 · Σ_s tr(W (I + H(q; x_s))⁻¹)`는 자세 q에서 뷰를 하나 더 찍은 뒤의 기대 사후 오차입니다.
   추정값과 표본 8개에 대해 평균합니다. `W`는 오차 척도의 단위(1 mm, 0.1°)입니다. 세 가지 형태를 씁니다.
   - 정확한 래스터 R: 후보 순위 결정 (`risk_exact.py`)
   - 정확한 기울기를 가진 매끈한 R̃: 최적화 (`risk_smooth.py`)
   - 캡슐 근사 R_cap: 거친 탐색 (`risk_capsule.py`)
4. **결정 (`decide.py`).**
   1. **시작점.**
      - 뷰 2: 자세 제약을 만족하는 Sobol 자세 320개를 R_cap으로 순위를 매기고, 0.25 m 다양성 규칙으로 8개를 고릅니다.
      - 이후 뷰: 직전 결정의 끝점들과 현재 자세를 시작점으로 씁니다.
   2. **거친 이동.** 각 시작점에서 R_cap에 SLSQP를 돌린 뒤 자세 제약 안으로 되돌립니다. 자세 제약은 자기 충돌,
      0.5 m 도달 범위, 작업공간·링크 간 여유 거리입니다.
   3. **인증.** 끝점들을 정확한 R 순서로 놓고, 현재 자세에서의 경로가 공개된 경로 검사를 통과하는 앞의 2개를 기준점으로
      삼습니다.
   4. **정밀화.** 각 기준점에서 log R̃에 신뢰영역 SQP를 정확한 기울기로 돌립니다. 다음 제약이 최적화 안에 들어
      있습니다(`constraints.py`, `trsqp.py`, `clearance.py`).
      - 0.5 m 도달 범위
      - 목표 자세의 작업공간·링크 간 여유 거리
      - 기준점에서 이어지는 관절 공간 직선 구간의 여유 거리
      - R̃ 근사의 유효 범위 상한
      - 관절 한계와 이동량 한도
   5. **선택.** 정밀화된 점과 기준점을 정확한 R 순서로 놓고, 공개된 최종 검사(`feasibility.py`)를 처음 통과하는 것을
      다음 자세로 정합니다. 통과하는 것이 없으면 3단계에서 남은 끝점들을 차례로 시험합니다.
      - 그래도 없으면 위험값이 가장 낮은 자세를 `unchecked` 표시와 함께 돌려줍니다.
      - 이때 `run()`은 `allow_unchecked=True`가 아니면 멈춥니다.
      - 명령줄은 `next_q_unchecked.txt`에 쓰고 종료 코드 3으로 끝납니다.
      - 실험의 D v4 결정 800번 중 1번 있었던 일입니다.

## 결과
xArm7 벤치마크 100장면, 정답 마스크, 모든 방법이 같은 첫 뷰를 씁니다. 표의 값은 k개 뷰 뒤의
`√c₂ = √((rot / 0.1°)² + (trans / 1 mm)²)` 기하평균입니다. 이것은 EasyHeC의 공개 오차 척도로, 추정값과 정답의
se(3) 로그에서 계산합니다.
- `rot`: 회전 부분 차이의 가장 큰 성분 (도)
- `trans`: 병진 부분 차이의 크기

| 방법 | k = 2 | 3 | 4 | 5 |
|---|---|---|---|---|
| **D v4 (이 코드)** | **0.0288** | **0.0216** | **0.0167** | **0.0159** |
| EasyHeC 뷰 선택 + nl_ls 적합 | 0.0396 | 0.0293 | 0.0255 | 0.0234 |
| 무작위 뷰 + nl_ls 적합 | 0.0620 | 0.0508 | 0.0410 | 0.0344 |
| EasyHeC (뷰 선택 + Adam 적합) | 0.413 | 0.324 | 0.319 | 0.293 |

실행 결과는 매번 정확히 같지는 않습니다.
- 공개된 경로 검사(MPLib RRTConnect, 0.1초 제한)에 시드가 없고, 결과가 CPU 속도에도 영향을 받습니다.
- 1e-14 수준의 부동소수 차이가 이후 결정을 바꿀 수 있습니다.

그래서 단일 실행이 아니라 장면 통계로 비교해야 합니다.
- 각 모듈은 실험 코드에서 D v4가 쓰지 않는 부분만 뺀 것입니다.
- 저장된 실험 상태에서 적합과 사후분포는 비트 단위로 같습니다.
- 경로 검사 전까지의 결정 단계는 1e-13 이내로 같습니다.

## 패키지 구성

| 모듈 | 내용 |
|---|---|
| `calibrator.py` | `Calibrator`: 입력, 반복, 기록 |
| `fit.py`, `posterior.py` | nl_ls 적합, Laplace 사후분포 |
| `geometry.py`, `se3.py` | 순기구학, 메시, 래스터라이저와 윤곽; 자세의 SE(3) 사상 |
| `risk_exact.py`, `risk_smooth.py`, `risk_capsule.py` | 위험값의 세 가지 형태 |
| `decide.py`, `trsqp.py`, `constraints.py`, `clearance.py` | D v4 결정, 신뢰영역 SQP, 제약, 거리장 |
| `feasibility.py` | 공개된 xArm 검사: 자기 충돌, 도달 범위, 경로(MPLib) |
| `robot.py`, `assets/xarm7/` | 로봇 모형 입력과 내장 xArm7 파일 (출처와 해시는 `SOURCE.md`) |
| `io.py`, `cli.py`, `config.py` | 자료 폴더 형식, 명령줄, 상수 |

## 한계와 안전

- **적용 범위.** 집게가 달린 xArm7과 고정 카메라 1대만 지원하며, 정답 마스크를 쓴 시뮬레이션에서만 검증했습니다.
  예측 마스크, 다른 로봇, 여러 카메라는 다루지 않습니다.
- **경로 검사.** 경로계획기는 EasyHeC의 가상 작업공간(경계 상자와 베이스 근처 바닥면)만 기준으로 검사합니다. 실제
  작업 공간은 반영하지 않습니다. 실제 로봇에서는 모든 동작을 사용자의 충돌 모형으로 계획하고 확인해야 합니다.
- **관절.** 제안되는 자세의 7번 관절은 0이고, 집게는 움직이지 않습니다(공개 프로토콜과 동일).
- **프로세스당 로봇 모형 하나, 보정 하나.** 모듈들이 프로세스 전체 상태를 가집니다.
- **GPU.** 코드는 `cuda:0`에서 돌아갑니다. GPU는 `CUDA_VISIBLE_DEVICES` 또는 명령줄의 `--gpu N`으로 고릅니다.
